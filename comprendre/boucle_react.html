Ce qu'il faut retenir

  

    
1 · LE SCHÉMA
Le LLM ne voit jamais votre code
Il reçoit le nom de l'outil, sa docstring et le schéma JSON des arguments. bind_tools joint ces schémas à chaque requête.

    
2 · LA DEMANDE
Le LLM demande, votre code exécute
Le LLM renvoie un AIMessage avec des tool_calls. Votre code appelle l'outil et répond par un ToolMessage qui porte le même tool_call_id.

    
3 · SANS MÉMOIRE
Le LLM relit toute la liste à chaque appel
La liste grandit, la requête aussi. Si le code ne renvoie pas l'historique, le modèle redemande la même chose jusqu'au garde-fou.

    
4 · CREATE_AGENT
La même boucle, en graphe
Deux nœuds, model et tools. On sort quand l'AIMessage n'a plus de tool_calls. Le garde-fou devient recursion_limit.
