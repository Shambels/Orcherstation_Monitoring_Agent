Ce qui change en v4

La plupart des tutoriels en ligne montrent encore la v3. Voici ce qui a bougé.

SujetLangfuse v3Langfuse v4 (ce kit)
Modèle de donnéesTables traces et observations séparées, reliées par jointureUne seule table d'observations, largement immuable. Une trace est l'ensemble des observations qui partagent un trace_id.
Écran TracingUn tableau Traces et un tableau ObservationsUn seul tableau, filtré par défaut sur Is Root Observation = true (une ligne par trace)
Attributs de tracePosés une fois sur la tracePropagés sur chaque observation (propagate_attributes) : sinon les agrégats par utilisateur ou par session sont incomplets
IngestionAPI batch /api/public/ingestionOpenTelemetry (/api/public/otel). L'API batch n'accepte plus que les scores.
Lecture par API/traces, /observations, /sessionsObservations v2, Scores v3, Metrics v2. Les anciennes routes répondent 404 en mode events_only.
SDKPython v2/v3, LANGFUSE_HOSTPython v4 (≥ 4.7 pour le temps réel), LANGFUSE_BASE_URL. Le SDK v5 exige un serveur ≥ 4.59.

Glossaire

Trace
Le traitement complet d'une requête : toutes les observations qui partagent un trace_id.
Observation
Une étape : generation (appel LLM), agent, tool, retriever, embedding, guardrail, chain, span, event.
Observation racine
L'observation sans parent. Son entrée et sa sortie sont celles de la trace.
Session
Les traces d'une même conversation, regroupées par session_id.
Environnement
Séparation des données : production, formation, sdk-experiment…
Release
Version de l'application qui a produit la trace (v1.3.0, v1.4.0…).
Score
Une évaluation : NUMERIC, BOOLEAN ou CATEGORICAL, attachée à une trace, une observation ou une session.
Prompt versionné
Un prompt stocké dans Langfuse, dont chaque modification crée une version. L'étiquette production désigne celle que charge le code.
Dataset, run
Un jeu de cas de référence, et une exécution (expérience) d'une variante sur ce jeu.
TTFT
Time to first token : délai avant le premier token généré. C'est la latence ressentie en streaming.
